# supergrep 구현 작업 인계

대상 실행 설정: 사용자가 지정한 **GPT-5.6 Terra / Ultra**.

이 파일은 후속 구현 작업에 넣을 요청문이다. 계획 작성 단계에서 goal을 시작하거나 모델 설정을 변경했다는 뜻이 아니다. 주 계획은 `docs/implementation-plan.md`다.

## 복사할 요청문

```text
/home/eunhhu/work/supergrep에서 supergrep v0.1을 구현하는 goal을 시작해줘.
이 작업은 GPT-5.6 Terra / Ultra로 실행할 예정이야.

먼저 docs/implementation-plan.md를 읽고 S0부터 S6까지 진행해.
현재 저장소 상태와 적용되는 AGENTS.md를 확인하고 기존 변경을 보존해.

목표:
코드·문서·설정을 포함한 UTF-8 텍스트를 자연어로 검색하는 Rust CLI를 만든다.
Linux ARM64 CPU 4코어 / RAM 8GB에서 실행하고,
모델 준비 후에는 네트워크·API 키·사전 인덱싱 없이 실제 로컬 ONNX 모델로 검색한다.
실제 파일 경로와 정확한 byte/line 범위, 사람이 읽는 출력과 JSON을 제공한다.
빠른 후보 검색과 --deep 전체 청크 평가를 모두 구현한다.

우선 S0에서 작은 영어 모델과 경량 다국어 모델을 실제 ARM 환경에서 실행하고
토큰화·batch score·runtime 호환성·시간·메모리를 확인해 기본 모델을 선정한다.
한국어/영어를 평가하되 한국어 질의로 영문 코드를 찾는 경우를 별도 집계한다.
모델 크기나 모델 카드 수치만으로 코드 검색 품질과 실행 속도를 판단하지 마.

진행 방식:
- 세부 구현은 계획의 인터페이스와 성공 기준을 지키면서 합리적으로 결정해.
- 매 단계의 변경, 실제 실행 명령, 결과 파일, 미완료 항목을 docs/progress.md에 기록해.
- model revision, artifact hash, tokenizer 규약, runtime 버전을 재현 가능하게 고정해.
- 일반 테스트에는 fake scorer를 쓸 수 있지만 제품과 실제 모델 검증을 대체하지 마.
- 검색 명령은 모델을 몰래 다운로드하거나 외부 API를 호출하지 않아야 해.
- 모델 오류를 lexical fallback으로 숨기거나 score를 관련성 확률로 표시하지 마.
- 탐색 누락, 처리 제한, lexical 근거 부족, fast에서 평가하지 않은 청크를 출력에 드러내.
- 속도 측정에는 매번 실행하는 CLI의 모델 로드 시간을 포함하고 batch 추론 시간도 별도 기록해.
- 평가 질의의 정답 경로나 표현을 구현에 하드코딩하지 마.
- 개발 집합에서만 조정하고 고정된 holdout 결과를 기록해.

범위:
v0.1에는 Tree-sitter, embedding/vector DB, 영구 검색 인덱스, 학습/증류,
자동 번역 LLM, GUI, MCP 서버, GPU 최적화, PDF/DOCX/OCR를 추가하지 마.
로컬 개발에 필요한 의존성·공개 모델을 준비하고 구현·검증·로컬 패키징까지 진행해.
원격 push, 공개 PR/release, registry publish, 다른 사람에게 메시지 전송은 요청 범위 밖이야.

완료 조건:
계획의 필수 테스트, 실제 모델 통합 검증, 오프라인 검증,
영어/한국어 품질 평가, ARM 시간/RSS 측정, 새 디렉터리의 배포 bundle 실행을 수행해.
README, 모델 선택 근거, evaluation/benchmark 결과, 검증 기록을 남겨.
최종 답변에는 실행 방법, 완료된 기능, 실제 검증 결과, 남은 제약을 요약해.

문제 처리:
목표에 미달하면 후보 누락과 모델 순위 오류를 구분하고 계획의 한도 내에서 개선해.
개발 집합에서 두 차례 개선한 뒤에도 핵심 품질/사용성 목표가 충족되지 않으면
증거와 구체적인 선택지를 남기고 필요한 범위 결정을 요청해.
모델 다운로드나 환경 제약으로 실행하지 못한 검증을 통과했다고 처리하지 마.
단순히 파일 작성이 끝났거나 테스트 일부가 통과했다고 goal을 완료하지 마.
goal 상태와 예산 처리는 실행 환경의 규칙을 따르고,
명시하지 않은 토큰 예산을 임의로 설정하지 마.
```

## 인계 시 확인할 사항

- 성능 기준 환경은 사용자가 ARM 4코어·8GB로 확정했다.
- 계획 작성 시 질의 언어는 한국어+영어를 기본 가정으로 두었다. 사용자의 추가 답변이 있으면 계획과 요청문에 함께 반영한다.
- 모델 프로필은 계획의 S0 평가로 확정한다. 원본 대화에서 나온 라이브러리·성능 주장을 검증 사실로 이어받지 않는다.
- 주 계획의 미구현 경로와 예시 명령은 후속 작업이 만들어야 할 항목이다.
